# 设备组管理与可信接入

通用管理能力适用于手机、桌面及其他 SDK 客户端，设备类型不决定权限。未启用签名管理的设备可显示本机信任列表，但不能将其当作服务端完整成员列表。

## 用户流程

1. 未入组设备可选择“创建新组”，填写组名和本机名称，自动成为首位管理员；也可选择“加入已有组”。服务端需为该应用启用自助创建。
2. 已有管理设备选择“添加设备”，显示二维码或复制邀请链接。邀请 10 分钟有效，最多一个申请者认领。
3. 新设备扫码/粘贴链接，在本机生成 Curve25519 私钥与公钥。登记请求使用独立的 Ed25519 签名密钥签名。
4. 邀请支持两种模式：`manual`（默认）由双方核对配对码，邀请方批准，可明确授予管理权限；`auto` 使用管理员签发的一次性授权，由扫码设备验证并自动加入，邀请端可离线，只授予普通成员权限。
5. 应用驱动 SDK 的 `finishJoin` / `finish_join`。SDK 验证批准或自动授权签名、本人公钥及请求摘要，保存可信成员名单并连接中继；自动模式无需邀请端轮询或人工批准。
6. 所有组成员可查看组成员和在线状态；管理员可添加、移除其他设备。离线设备仍在成员列表中。

扫码或粘贴邀请是初始信任渠道，不应接收不可信来源的邀请。服务地址不能携带用户凭据、查询参数或片段；HTTP 重定向被禁止。组管理不会自动打开剪贴板共享权限。

## 权限及生命周期

- 邀请者必须是当前名单中的管理员；接入令牌本身不能签署成员变更。
- 普通成员可读，不能创建邀请、批准或移除设备。新成员默认无管理权限。
- “退出当前组”仅移除本机；其他设备继续使用。最后一位管理员在仍有其他成员时不能直接退出，应邀请另一位管理员或解散组。只有本机时退出会关闭空组。
- “解散设备组”仅管理员可用，生成带 `closed: true` 的空成员签名终止记录，撤销全组令牌和待处理邀请；终止组不能复活，创建新组使用新 ID。客户端明确确认后清理本机公网组配置，保留历史、局域网配置和本地密钥，并为下次接入生成新的中继设备 ID。
- 普通成员可修改自己的组内显示名称；管理员可修改任一成员名称。每次签名变更只修改一人的名称，不改变身份、公钥或权限。
- 删除在事务中撤销设备令牌，终止该设备的在线连接，并取消它尚未完成的邀请。删除不会抹除其已经下载的数据或阻断独立 LAN 通道。
- 不复用已撤销的设备 ID。需要重新加入时创建新设备 ID。
- 每组最多 32 位成员、16 个未到期邀请；管理记录达到 4096 条后停止新增/升级成员及改名，仍允许删除。过期邀请与初始化凭据每分钟清理。
- 邀请及申请保存于客户端私有存储；页面关闭不丢失。SDK 不创建常驻轮询；应用自行驱动待处理申请与完成加入，自动模式显示“正在加入”，手动模式显示“等待批准”。自动邀请中的临时委托私钥不可上传服务器、写日志或长期保留。
- 所有令牌及邀请秘密在服务器只存 SHA-256 哈希。新设备接入令牌由客户端随机生成，提交哈希；服务端不需要保存或返回明文令牌。

## 自助创建新组

`POST /relay/v1/group/create` 接收 `{entry, token_hash}`。客户端本地生成身份、令牌及随机 `g-<32位小写十六进制>` 组 ID，签署 revision=1 的单成员名单；新增可选 `name` 为组显示名称（UTF-8 最多 128 字节），后续成员变更必须保留名称。私钥与明文令牌不发送到服务器。

服务端默认关闭自助创建，使用 `serve --self-service-apps example` 按应用启用。创建只接受本人作为唯一管理员的有效签名，拒绝已有设备组及保留的初始化组；全服务最多 1000 个自助组、每小时最多 20 个，配额持久化在 `group_creations`，超限返回 429。此接口用于允许自助注册的部署，应用名称不是账户认证。

四种 SDK 使用 `prepareCreate`（Python `prepare_create`）生成 `pending_create`，应用先保存草稿，再调用 `create`。响应丢失或重启后复用同一份已签名请求；只有同一初始签名和仍有效的原令牌哈希可幂等成功，不能修改组或替换设备。成功后持久化已验证名单并清理草稿。已入组设备应继续使用当前组，切换组由应用显式发起。

## 初次初始化与现有设备迁移

管理员仅首次需要在服务端执行（输出路径必须不存在）：

```sh
common-relay group-bootstrap --data /var/lib/common-relay \
  --app example --group personal --credential-out /private/path/bootstrap.json
```

将这份短时有效的初始化邀请经可信渠道交给首台设备，在客户端确认服务地址后导入。新组由首台设备本地生成密钥，并存入私有存储。这个运维入口用于已有组迁移或未开放自助创建的部署；新用户优先使用“创建新组”。

已有组初始化必须保留服务器所有未撤销设备的公钥；首台设备应已固定这些可信公钥。初始化签名名单中的旧成员没有管理签名公钥，仍可使用原传输配置。旧成员通过管理员的新邀请补齐签名公钥、验证管理根，保持原设备 ID、Curve25519 私钥、公钥和令牌不变，可在批准时授予管理权限。不得以服务器返回的名单代替这一步初始信任确认。

启用签名管理后，`device-add` / `device-revoke` 拒绝绕过名单直接修改该组。管理员全部丢失时不能自动恢复管理权：需要管理员恢复可信备份，或创建新组并重新可信配对；本版没有可绕过端到端信任的网页重置入口。

## 签名名单及可靠性

每条记录包含 Base64 `payload`、十六进制 Ed25519 `signature`、`signer`。签名覆盖 payload 解码后的原始 UTF-8 字节，避免跨语言 JSON 序列化顺序影响。签名私钥种子为：

`SHA256(UTF8("common-relay/group-signing/v1\0") || Curve25519 私钥32字节)`

用途分离的签名密钥只在本地派生。名单携带各设备传输公钥及签名公钥；邀请二维码固定邀请者签名公钥。普通客户端按已固定的名单验证下一条签名者当时具有管理权限、revision 连续、previous 为前一 payload 的 SHA-256，再接受变化。

每次事务允许增加一名成员、升级一名保留原传输公钥的旧成员、移除一名成员、修改一名成员名称，或由管理员解散全组。不得静默替换现有身份公钥。新增/升级记录还绑定邀请 ID 和原申请 payload 摘要。并发修改返回 409，客户端刷新再重试，不能覆盖较新名单。配对码为申请 payload SHA-256 的前 12 个十六进制字符，分为三组供用户核对。

客户端私有配置保存最后验证的签名记录和可信公钥表；从该 revision 增量读取最多 64 条记录一页。在线客户端收到 `group.changed` 后重连，在连接前拉取并验证更新；离线客户端下次连接时验证。服务器可拒绝服务或隐藏更新，但不能在已固定信任链后伪造新成员；本机制不提供全球一致性证明或抵抗服务器分叉的外部透明日志。

SDK 的配置变更需要应用持久化。应用应在接入申请前保存本机密钥/令牌草稿，发送后保存原申请，恢复时复用原申请；批准响应丢失可通过已签名记录恢复。所有请求超时 15 秒，响应上限 3 MiB，禁止跨源跳转。持久化失败必须报告，不把未保存身份当作接入成功。

## 验证

- `go test -race ./...`：服务端测试。
- Python `test_groups.py`：临时本地服务、手机邀请手机、普通权限拒绝、认领竞争、过期/取消、移除、恢复与旧身份升级。
- `protocol/group-vectors.json`：各 SDK 共享签名、成员变更和反回滚材料，全部为公开测试身份。
- `scripts/group-interop.py`：Swift/Dart/Java 分别与 Python 完成实际登记、邀请、批准、移除；不读取真实客户端配置。
- 现有消息/8 MiB 双向流互通继续运行，组管理测试不代替公网部署、手机摄像头或长期运行验收。

## 退出、解散与失败恢复

各 SDK 使用 `prepareExit`（Python `prepare_exit`）刷新并准备签名请求，应用保存 `pending_exit` 后调用 `exit`，向 `/relay/v1/group/exit` 提交签名变更。普通成员仅可签署自己退出或改名；管理员可签署成员管理或全组解散。退出后令牌立即撤销，专用退出端点仅允许原凭据重复确认完全相同的已提交退出记录，不能再访问组或执行其他操作。

应用将退出草稿按服务器、组、设备与令牌绑定，避免旧操作影响后来加入的新组。网络失败保留配置和草稿；已被撤销的设备可在明确选择退出后清除本地配置，但不能冒充成功解散远端组。UI 将退出/解散放在独立区域，展示影响范围并确认；设备操作菜单提供改名及有权限时的移除。

客户端若在读取组管理状态时收到 401，必须将本机组接入标记为失效，隐藏缓存成员、管理员操作和邀请，展示返回创建/加入的入口。401 本身不区分解散和本机被移除，因此不能冒充已取得最新名单；用户确认后只清除本机公网组配置，保留私钥、历史和 LAN 配置。普通成员退出后，仍在组内的管理员可继续邀请，已有组不得因其他人的退出而重建。

## 自动邀请的接入与升级

创建邀请可选模式：Python `await groups.invite(mode="auto")`，Swift `try await groups.invite(mode: "auto")`，Dart `await groups.invite(mode: 'auto')`，Java `groups.invite("auto")`。省略参数保持手动确认。

自动邀请仍是 10 分钟、单个申请认领。管理员预先签署限时授权，授权固定组、邀请 ID、临时委托公钥和可信成员链起点；扫码设备持有二维码内的临时私钥，验证从起点到当前版本的完整成员链，再签署只添加自己的普通成员变更。中继不持有任何签名私钥。完整字段、HTTP 接口、并发及响应丢失处理见[协议](../protocol/README.md#invitation-approval-modes)。

`join` 提交申请后，调用 `finishJoin` / `finish_join` 自动完成余下步骤，无需邀请端执行 `approve`。请求冲突返回 409 时保留草稿，下次 finish 自动读取新名单并重新签署；已成功但响应丢失时，finish 验证原批准记录并恢复。自动模式不支持升级旧手动身份，旧身份升级继续使用手动邀请。

启用前须更新组内所有成员 SDK；旧 SDK 无法验证自动入组签名，会拒绝后续更新。入组不改变各应用的剪贴板、ADB 或远控业务授权。

## 短邀请链接

短邀请把完整内容存为服务器不可解密的 SecretBox 密文，链接只包含中继域名、22 字符邀请 ID 和 43 字符解密密钥。链接长度随域名变化，SDK 通过 compact 参数启用短邀请。扫码方从中继取得密文、校验解密后沿用原有签名入组流程，兼容原长邀请。

各 SDK 均提供短邀请编码与解析。读取鉴权只发送与密钥用途隔离的派生凭据，不上传链接密钥或自动授权私钥。保留 10 分钟、单次使用、取消和两种审批模式。
