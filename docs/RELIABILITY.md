# 离线可靠性与状态清理

本页描述 SDK 与服务端的离线重试、去重、持久化和资源清理约定。应用接入时应使用私有持久化目录，并独立验证断线恢复。

## 持久化接入

在线发送、流接口保持原有用法，不自动重放。离线发送和接收必须配置持久化存储；缺失时明确报错，不静默降级为内存去重。

| SDK | 接入 | 显式清理 |
|---|---|---|
| Python | `Client(..., state_path=private_db_path)`；兼容已有 SQLite 表并迁移 | `client.cleanup()` |
| Swift | `RelayJournal(directory: privateURL)`，传入 `RelayClient(identity: ..., journal: journal)` | `try journal.cleanup()` 或 `try await client.cleanup()` |
| Java | `new RelayJournal(privatePath)`，传入四参数 `RelayClient` 构造器 | `journal.cleanup()` 或 `client.cleanup()` |
| Dart | `RelayJournal(privateDirectory)`，传入 `RelayClient(identity, journal: journal)` | `journal.cleanup()` 或 `client.cleanup()` |

每个状态目录/数据库只允许一个存储实例拥有；重连复用同一实例或关闭旧客户端后重新打开。Swift/Java/Dart 使用逐记录原子替换的文件存储，Python 保留 SQLite；不新增数据库运行时依赖。目录放在应用私有数据区，不使用下载目录或共享同步目录。记录按应用、组、本机设备和对端/消息 ID 隔离，不保存令牌、私钥或消息明文。

客户端连接存续期间每小时清理，存储打开时也清理；关闭客户端会停止定时任务。每轮最多处理 256 条过期发送记录和 256 条接收记录（文件型存储为合计 256 次变更）。大量积压可多次调用显式清理。损坏记录/写入失败会报告错误，不能在未持久化成功时发送 ACK。

## 消息生命周期

- 应用为一次逻辑发送保存随机消息 ID。重试使用同一 ID；SDK 将接收方、内容摘要、原密文和首次有效期先持久化，再发送。相同 ID 不同内容或接收方被拒绝。
- 新离线消息默认有效期 24 小时；Python 可在 1–86400 秒内指定 TTL。重试使用固定绝对 `expires`，不能因重连延长。密文内也绑定相同有效期，防止清理去重记录后重放过期消息。
- `stored` 只表示服务器已保存，客户端仍保留密文。`received` 表示接收方确认；SDK 删除密文，保留终态 7 天。服务器不主动推送最终回执，发送方显式以同 ID 重试可查询确认结果。
- 未确认消息到期后，清理器删除密文并保留过期终态至原有效期后 7 天；重试明确失败，不生成新 ID 重发。终态清理后 SDK 不再记忆该 ID，应用不得把清理后的旧 ID 当作新操作重用。
- 接收方在业务事务提交后调用 `acknowledge`，SDK 先保存去重记录再发 ACK；ACK 丢失后的重投会重新 ACK，不再次交给业务。去重记录保留 7 天，不因重复 ACK 无限延期。
- SDK 去重无法与应用数据库自动组成同一事务。应用仍须按消息 ID 幂等，处理“业务已提交，但尚未调用 acknowledge 就崩溃”的窗口。未确认消息允许再次投递。
- Python 历史表没有有效期：迁移时保留密文和接收记录 7 天，历史发送记录标记 `legacy`，拒绝再次发送，避免重新赋予 TTL；到期清理。确需重新发送由用户/业务发起新操作。
- Swift 的 `acknowledge(id:from:offline:)` 新增默认参数；处理离线事件应传 `offline: true`。其他 SDK 从事件读取 offline 标志。

## 服务端并发与清理

文件上传、提交、删除、过期清理共用每文件互斥锁。不同文件的网络读取、写盘、SHA-256 校验不持有全局文件锁；数据库配额预留仍在事务内串行执行。下载打开文件后释放对象锁。锁有引用计数，最后一位使用者离开即释放锁表条目。

已有每分钟服务端清理继续删除到期消息、回执、文件及撤销设备关联内容。文件删除失败保留数据库记录和配额，记录错误并继续清理其他对象，下轮重试；不会删除用户下载文件、身份凭据或备份。

每设备 8 条流同时约束双方，待接受流也计数。活跃连接每秒心跳检查并清理超过 40 秒未接受的流，关闭时通知双方；全部连接关闭时不残留流。不新增服务关闭后继续运行的后台任务。

## 验证边界

本地验证包括断连重试、丢失回复/ACK、进程重建状态、清理时间边界和批量限制、旧表迁移、同文件并发操作、慢上传跨文件隔离、删除失败重试、接收端流上限、无后续请求的超时回收，以及四类 SDK 密码向量与本地互通。它们不替代生产换网、三应用混合负载、24 小时运行或备份恢复演练。
